## Executive Summary

Financial fraud is one of the most computationally challenging problems in modern applied machine learning due to extreme class imbalance (typically $\le 0.15\%$ fraudulent records), adversarial data generation, and the catastrophic financial cost of False Negatives (missed fraud). Standard off-the-shelf classifiers operating under default $0.50$ decision thresholds achieve deceptive $\approx 99.87\%$ accuracy while missing $100\%$ of fraudulent transactions.

**F.R.A.U.D.S.H.I.E.L.D.** is a production-grade, end-to-end Machine Learning fraud detection system built to solve this challenge. Across a 12-phase systematic development lifecycle, we designed, benchmarked, optimized, and deployed an explainable AI pipeline capable of sub-20ms real-time scoring and bulk CSV batch audits.

## 1. Data Engineering & Preprocessing Architecture

### Theoretical Foundation of Financial Discrepancies
In standard financial ledgers, legitimate transactions follow conservation of balance principles:
$$\text{newbalanceOrig} = \text{oldbalanceOrg} - \text{amount}$$
$$\text{newbalanceDest} = \text{oldbalanceDest} + \text{amount}$$

In fraudulent scenarios (e.g., account takeover, unauthorized wire draining), balance discrepancies occur systematically because attackers siphon funds to mule accounts or liquidate balances to zero. We engineered two continuous features capturing this discrepancy:
1. `errorBalanceOrig`: Source account discrepancy:
   $$\text{errorBalanceOrig} = \text{newbalanceOrig} + \text{amount} - \text{oldbalanceOrg}$$
2. `errorBalanceDest`: Recipient account discrepancy:
   $$\text{errorBalanceDest} = \text{oldbalanceDest} + \text{amount} - \text{newbalanceDest}$$

### Data Leakage Guards
- **Target Leakage**: In the PaySim dataset, the synthetic feature `isFlaggedFraud` is generated by an arbitrary heuristic rule ($\text{amount} > 200,000$). Leaving this feature in the dataset causes models to overfit to synthetic rules rather than authentic fraud dynamics. It is strictly discarded.
- **Overfitting Identifiers**: High-cardinality account IDs (`nameOrig`, `nameDest`) are removed prior to vectorization to guarantee models generalize to unseen accounts.
- **Robust Outlier Normalization**: Financial transaction amounts follow heavy Pareto-tailed distributions ($0.01$ to $\$10,000,000+$). `RobustScaler` (median & interquartile range) is used instead of `StandardScaler` to prevent extreme outliers from crushing variance.

## 3. Threshold Calibration & Imbalance Resolution

Under severe class imbalance, the default decision threshold ($t = 0.50$) produces $0\%$ recall. By analyzing the Precision-Recall curve, we calibrated the optimal decision threshold:
$$t^* = 0.09$$
Operating at $t^* = 0.09$ elevated test recall from **0.00% to 85.42%**, successfully capturing the vast majority of fraudulent events while maintaining high precision.

## 4. Explainable AI (SHAP) Attribution

To satisfy regulatory explainability requirements (e.g., Fair Lending, GDPR Article 22, FCRA Adverse Action), each inference output includes Game-Theoretic Shapley values:
- **Global Importance**: `errorBalanceOrig` and `errorBalanceDest` contribute over $40\%$ of overall model gain, followed by transaction type (`TRANSFER` and `CASH_OUT`).
- **Local Waterfall Attributions**: Individual API predictions return top risk-elevating drivers and mitigating factors with human-readable plain-English summaries.
